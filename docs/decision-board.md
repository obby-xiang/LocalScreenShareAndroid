# 决策看板

> 用途：集中记录已经形成的技术裁决、当前状态、依据和复审条件，避免把“设计目标”误读成“已经实现”。
> 重要边界：**裁决不等于已实施。** 本页所有“未实施”项都没有经过设备、网络或性能实测；验证证据必须单独记录，不能用设计推理代替。
> 当前依据：`docs/` 中的静态审查与设计文档（提交 `7a8a05d`）以及当前仓库代码。当前代码仍是 JPEG + gRPC 路径，本页的目标设计尚未落地。

## 状态口径

| 状态 | 含义 |
| --- | --- |
| 已裁决·未实施 | 方向已确定，代码尚未按此实现 |
| 已裁决·当前实现符合 | 当前代码或构建配置已经满足，无需额外改造 |
| 已裁决·文档约定生效 | 文档与协作规范已经生效 |
| 待验证 | 需要实测或产品确认后才能定稿，不能写成永久结论 |
| 已否决 | 已明确不纳入当前产品前提，除非前提改变 |

## 维护方式

- 新增裁决时分配稳定 ID，写清“当前裁决、状态、理由、重新评估条件”，并链接到设计文档。
- 只有代码、测试或实测记录能改变“未实施”状态；设计文档更新不等于实现完成。
- 状态变为“已实施”时，补充对应提交、测试输出或实测证据；没有证据时保持“未实施”或“待验证”。
- 触发条件满足或产品前提变化时，复审相关裁决；被推翻的裁决保留 ID 并标记“已否决”及原因，不静默删除。
